Pipeline Architecture and Live Verification

Tekton Pipeline Stages

Sequential execution workflow
  1. 1
    Clone Source
    Retrieves the repository from GitHub into a shared PersistentVolume Workspace and outputs the verified commit SHA.
    Task: clone-source • alpine/git
  2. 2
    Install & Test Quality Gate
    Executes clean npm ci and unit tests with node:test. Failure halts the pipeline immediately before building.
    Task: test-application • node:20-alpine
  3. 3
    In-Cluster Image Build
    Builds the production Docker image inside the Kubernetes pod using Kaniko and pushes versioned tags to Docker Hub.
    Task: build-and-push-image • Kaniko Executor
  4. 4
    Rolling Kubernetes Deployment
    Updates deployment manifests with the verified container image, monitors rollout status, and confirms endpoint readiness.
    Task: deploy-application • kubectl 1.37

System Context

Local Execution
All build and deploy operations execute entirely within the local Minikube cluster on Windows 10 without requiring cloud compute resources.
External Registries
GitHub serves as external VCS and Docker Hub serves as the external OCI container registry, authenticated through Kubernetes Secrets.
Automated Gating
PipelineRun sequential dependencies guarantee that any failing unit test halts container builds, preventing defective deployments.
